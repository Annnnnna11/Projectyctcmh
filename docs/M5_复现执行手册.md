## 3. 分段预处理规格（按 store 生成特征）

使用 `src/1_preprocessing_by_store.py`，以官方只读基线中的全局 `1. preprocessing.py` 为参照。**特征定义、列名、列顺序、dtype 压缩全部与官方一致**，只改"在哪个粒度上算"。

### 3.1 产物布局

```
data/processed/

│   ├── grid_part_2.pkl
│   ├── grid_part_3.pkl
```

### 3.2 执行结构

```text
[全局一次，都是小表]
  读 calendar → 生成 grid_part_3 所需的日历特征表（1969 行）
  读 sell_prices → 生成价格特征表（约 680 万行，按 store×item 分组）+ release 表
  从 sales_train_evaluation 取 id/item/dept/cat/store/state 的全局类别表 GLOBAL_CATS

[循环 10 个 store，一次只留一个店在内存]
  取该店 3049 行宽表 → melt → 追加 d_1942..d_1969 空行 → release 过滤   → grid_part_1
  merge 价格特征表                                                    → grid_part_2
  merge 日历特征表                                                    → grid_part_3
  groupby('id') 生成 lag / rolling / tmp_rolling                      → lags_df_28
  对 11 组编码键累计 count / sum / sumsq（遮 d>1913 后）              → 暂存小表
  reduce_mem_usage → 落盘 → del + gc.collect()

[全局一次] 合并 10 店的 count/sum/sumsq → 得到每组的 mean / std

[再循环 10 个 store] 读 grid_part_1 → 按编码键回填 mean/std → mean_encoding_df → 落盘
```

### 3.3 三条必须遵守的规则

**规则 1（P0）：目标编码必须两遍算，不能在店内直接 transform。**
11 组编码键里，含 `store_id` 的 4 组（`store_id`、`store_id×cat_id`、`store_id×dept_id`、`item_id×store_id`）店内即完整；其余 7 组（`state_id`、`cat_id`、`dept_id`、`state_id×cat_id`、`state_id×dept_id`、`item_id`、`item_id×state_id`）**跨多个店**，店内 transform 只看到部分数据，数值会错且不报错。统一用两遍法：

```python
# 第一遍（每店）：遮 d > 1913 后按键累计，用 float64 防精度损失
s = sales.astype('float64')
part = df.assign(s=s, ss=s*s).groupby(keys, observed=True).agg(n=('s','count'), s=('s','sum'), ss=('ss','sum'))

# 合并（全局）：parts 按 keys 相加
tot  = pd.concat(parts).groupby(level=list(range(len(keys))), observed=True).sum()
mean = tot.s / tot.n
std  = np.sqrt((tot.ss - tot.s**2 / tot.n) / (tot.n - 1))   # 等价 pandas 默认 ddof=1

# 第二遍（每店）：按 keys 回填，必须保持 grid_part_1 的行序与 index
```

自检：对 `store_id×dept_id` 这类店内完整的键，两遍法结果应与店内 `groupby(keys)['sales'].transform('mean'/'std')` 一致（误差在浮点精度内）。

**规则 2（P0）：类别列必须用全局固定类别表。**
不能每店各自 `astype('category')`：

```python
for col in ['id','item_id','dept_id','cat_id','store_id','state_id']:
    df[col] = pd.Categorical(df[col], categories=GLOBAL_CATS[col])
```

否则各店类别编码不同，训练和预测的类别映射对不上；递归预测拼接多店网格时，列还会退化成 object，LightGBM 直接报错。事件列（`event_name_1` 等）同理，类别表从全量 calendar 取。

**规则 3（P1）：5 张表行对齐 + index 全局唯一。**
- 每店的 5 张表必须**行数相同、index 相同、行序相同**（官方 `concat(axis=1)` 的对齐不变量，见技术文档 3 节"设计哲学"）；
- index 用 `店序号 × 10_000_000 + 店内行号`（单店约 600 万行 < 1e7），保证多店拼接时 index 不重复；
- 落盘前断言：`assert all(t.index.equals(g1.index) for t in [g2, g3, lags, enc])`。

### 3.4 与官方的差异边界

| 项 | 与官方关系 |
|----|-----------|
| grid_part_1/2/3、lags_df_28 | **数值等价**（release、价格、日历、按 id 的 lag/rolling 都不跨店） |
| mean_encoding_df | **等价，前提是规则 1 执行到位**；std 的计算方式不同，浮点末位会有差异，经 float16 压缩后可忽略 |
| 类别编码整数值 | 可能与官方不同（类别表顺序不同），不影响模型效果 |
| 文件组织 | 5 个全局 pkl → 10 店 × 5 个 pkl，所以训练 / 预测脚本的读取处要改（补丁 #9） |

## 4. 兼容性补丁清单（跑之前必须打完）

**P0 不改 = 结果错但不报错**，最危险。

| # | 级别 | 位置 | 官方写法 | 改为 | 不改的后果 |
|---|------|------|----------|------|-----------|
| 1 | P0 | 3 个递归 PREDICT | `base_test[TARGET][mask] = estimator.predict(...)` | `base_test.loc[mask, TARGET] = estimator.predict(grid_df.loc[mask, MODEL_FEATURES])` | 预测值写不回去，28 天全用旧特征，**结果错但不报错** |
| 2 | P0 | 预处理 + 6 个 TRAIN | `grid_df['sales'][grid_df['d'] > X] = np.nan` | `grid_df.loc[grid_df['d'] > X, 'sales'] = np.nan` | 标签遮不住 / 未来行不为 NaN |
| 3 | P0 | 分段预处理 | —— | 规则 1、规则 2（3.3 节） | 目标编码错 / 类别错乱 |
| 4 | P1 | 分段预处理 | `date.dt.week` | `date.dt.isocalendar().week.astype(np.int16)` | AttributeError |
| 5 | P1 | 6 个 TRAIN | params 里 `'n_estimators': 3000`、`'verbose': -1` | `'num_iterations': 3000`（删 n_estimators）、`'verbosity': -1` | 报错或训练轮数不对 |
| 6 | P2 | 分段预处理 | `transform(lambda x: x.shift(n))` | `groupby('id')['sales'].shift(n)` | 功能等价，lambda 版极慢 |
| 7 | P2 | 分段预处理 reduce_mem | 含 NaN 列强转 `float16` | 溢出列退回 `float32` | numpy 2.x overflow |
| 8 | P1 | 训练 / 预测脚本 | 读 5 个全局 pkl | 改读 `processed_data_dir + f'{store}/xxx.pkl'` | FileNotFoundError |
| 9 | P1 | 3-1 集成脚本 | 固定读 6 个文件 | 改为读列表 `SUBS`（A 轮 2 个、B 轮 6 个），输出名随轮次 | A 轮无法集成 |
| 10 | P3 | 6 个 TRAIN 循环头 | 无 | `if os.path.exists(bin_path): continue` | 中断后全部重训 |
| 11 | P3 | 按 store 循环的脚本 | 无 | 单店开关（见下） | 无法做小闭环 |

## 6. 低内存执行红线（10GB RAM）

摘自 `M5_memory_and_low_RAM_pipeline_summary.txt`，浓缩为执行期必须遵守的 7 条：

1. 一次内存里只留**一个 store** 的数据（分段预处理和训练循环都遵守），不要"优化"成全局 concat。
2. 保留 `reduce_mem_usage`（float16 / int8 压缩）和所有 `del ...; gc.collect()`。
3. 每次 `lgb.train` 前 `free -h` 确认还有明显空闲 RAM；pandas 已占满 = 训练必崩（LightGBM 建 Dataset 还要额外内存）。
4. **swap 只是保险，不能当内存用**：出现"CPU 占用低 + 磁盘 IO 高 + 程序几乎不动"= swap 抖动，立即停进程降峰值，不要硬等。
5. 中间产物落 E 盘；若 IO 成瓶颈，把 `data/processed/` 移到 WSL 原生盘（如 `~/m5proc/`）再软链回来。
6. 一次只跑一个训练 / 预测进程。
7. 预处理两遍法的累计表只保留 `n / s / ss` 三列聚合结果，不保留明细行。
