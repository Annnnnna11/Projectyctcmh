## 1. 项目背景与竞赛目标

### 1.1 任务定义

Walmart 提供了 **3049 个商品（SKU）** 在美国 **3 个州（CA / TX / WI）、10 家门店** 从 **2011-01-29 到 2016-06-19** 的日销量数据。任务是预测每个 `商品 × 门店` 序列在未来 **28 天** 的日销量。

数据的层级结构（12 个聚合层级）：

```
state_id (3)  →  store_id (10)  →  cat_id (3)  →  dept_id (7)  →  item_id (3049)
```

- `cat_id`：3 个大类 —— `HOBBIES`、`HOUSEHOLD`、`FOODS`
- `dept_id`：7 个小类 —— 如 `FOODS_1`、`HOBBIES_2` 等
- 最底层序列数：`3049 items × 10 stores = 30490` 条时间序列

### 1.2 评估指标：WRMSSE（Weighted Root Mean Squared Scaled Error）

WRMSSE 是主办方定义的 12 层级加权指标，包含逐序列 RMSSE 的尺度项和基于最近 28 天 dollar sales 的序列权重。为避免用过度简化的单层公式误导，本文不复写简化公式；层级聚合、尺度分母、权重归一化和特殊序列处理均以竞赛 Evaluation 页面与官方 M5 定义为准。

关键点：
- RMSSE 的尺度来自训练历史的一阶差分平方均值，使不同量级的序列可比；
- WRMSSE 的**官方指标权重**由主办方规则确定，依据最近 28 天的 dollar sales（units × sell_price）计算，不是可调超参数；
- 第 5 节的**模型集成融合权重**只决定多份预测如何合成，与 WRMSSE 官方指标权重是两套完全不同的权重。

> 本轮目标是跑通预测 pipeline，**不实现本地 WRMSSE 评分器**。需要评分时必须按官方定义另行实现或采用经核验的 evaluator，不能用本文的说明性文字代替正式公式。

> 实践含义：虽然指标是 WRMSSE，但**几乎所有 top 方案都不直接优化 WRMSSE**，而是用 **Tweedie / Poisson loss** 训练 LightGBM——因为销量是"含大量 0 的非负计数"，Tweedie 分布天然契合。第一名同样如此。

## 2. 第一名方案总览（先看全局）

### 2.1 一句话概括

> **用 6 个"模型族"、共 220 个 LightGBM 回归模型（Tweedie loss），在 3 种分组粒度 × 2 种预测模式下分别训练，最后把 6 份提交结果做简单算术平均。**

### 2.2 两个正交的拆分维度

**维度 A —— 分组粒度（把大数据切成小数据分别建模）：**

| 粒度 | 分组键 | 模型数 | 直觉 |
|------|--------|--------|------|
| store | `store_id` | 10 | 同店共享促销 / 气候 / 节假日 |
| store × cat | `store_id × cat_id` | 10×3 = 30 | 再按大类细分 |
| store × dept | `store_id × dept_id` | 10×7 = 70 | 最细，按小类细分 |

**维度 B —— 预测模式：**

| 模式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **Recursive（递归）** | 逐天预测，第 t 天预测值回填当作第 t+1 天的 lag 特征，循环 28 次 | 精度高（特征始终"新鲜"） | 误差累积、不稳定 |
| **Non-recursive（非递归 / 直接）** | 只用真实历史 lag（≥28 天前），一次性预测全部 28 天 | 稳定、无误差累积 | 精度略低（lag 较"旧"） |

> 作者在 Writeup 中明确：他测了两种模式的均值和标准差，发现**递归更准但方差大，非递归更稳**，于是**两者融合**，兼顾精度与稳定性。这是方案的核心洞察之一。

> **初学者澄清 · "精度高"和"不稳定"不矛盾（说的是两个不同统计量）。**
> - **"精度高"指平均值**：跨很多序列、很多验证窗口平均下来，递归的 WRMSSE 更小（越小越好），因为它每天用最新鲜的特征（含自己前几天的预测），跟得上近期变化。
> - **"不稳定 / 误差累积"指散布（方差/std）**：不是均值大，而是递归的 WRMSSE 在不同窗口/不同商品上忽好忽坏、个别情况特别差——因为某天的预测会回填成下一天的特征，一步错会沿 28 天滚雪球。
> - 非递归相反：28 天一次性从固定的旧特征产出，错误不滚雪球→稳定；但信息"陈旧"、跟不上近期变化→平均略差。
> - 即**递归=低偏差高方差，非递归=略高偏差低方差**；平均二者=降方差、保住大部分精度（经典 ensemble / bias–variance 权衡）。作者实测：递归 mean 低、std 大；非递归 mean 略高、std 小。

### 2.3 组合出 6 个模型族 = 220 个模型

```
递归:    store(10) + store_cat(30) + store_dept(70) = 110 个模型
非递归:  store(10) + store_cat(30) + store_dept(70) = 110 个模型
                                            合计 = 220 个模型
```

对应 6 份提交文件，最终 **等权平均**：

```
final = (sub1 + sub2 + sub3 + sub4 + sub5 + sub6) / 6
        └─────── 递归 3 份 ──────┘ └────── 非递归 3 份 ─────┘
```

### 2.4 全部模型的共同点

- **算法**：LightGBM（GBDT）
- **目标函数**：`tweedie`，`tweedie_variance_power = 1.1`（接近 Poisson=1.0，适配零膨胀计数）
- **评价指标**：`rmse`（仅用于训练时监控，非最终指标）
- **learning_rate**：0.015，`n_estimators`：3000（无早停，固定轮数）
- **正则**：`subsample=0.5`、`feature_fraction=0.5`、`max_bin=100`、`boost_from_average=False`
- 递归 store 模型更大（`num_leaves=2^11-1`），其余多为 `2^8-1`

### 2.5 方案的演进：从"分类"探索到"纯回归"落地

作者的两个探索性 notebook（也是你链接里的）体现了他的思考路径：

1. **`M5 - Cluster zero / one sales pattern`**：观察到大量序列是"间歇性需求"（大量 0，偶尔 1）。尝试按 **0/1 销量模式聚类分组**，对不同模式的商品用不同策略。
2. **`M5 - Mean Encoding for Classify/Regression`**：探索把问题当**分类**（明天卖不卖得动？0 vs 1 vs ≥2）还是**回归**，并研究 **mean encoding（目标编码）** 特征的效果。
3. **`Grouping Items by Stockout Pattern`（jpmiller）**：社区思路——按"缺货模式"给商品分组，识别因缺货导致的 0 销量（并非真实无需求）。

> **最终落地版本（A1 官方代码）做了简化**：放弃了显式的"分类 + 回归两阶段"，直接用 **Tweedie 回归** 一把梭；分组思想则保留为 **store / cat / dept 多粒度建模 + mean encoding 特征**。理解这一点很重要——**你要复现的是 A1 这套干净的回归集成，而不是探索期的分类方案**。分类/聚类的想法留作你后续"对照组"的素材（见第 10 节）。

## 3. 数据与特征工程详解（preprocessing）

本机当前执行入口：`src/1_preprocessing_by_store.py`。
官方全局脚本 `src/M5-methods/Code of Winning Methods/A1/3. code/1. preprocessing/1. preprocessing.py` 仅作为只读参考基线，不作为本机执行入口。
本机产物：`data/processed/{store}/` 下每店 5 个 pickle。

```
grid_part_1.pkl      # 基础网格：id 索引列 + sales + release
grid_part_2.pkl      # 价格特征
grid_part_3.pkl      # 日历特征
lags_df_28.pkl       # 滞后 + 滚动特征
mean_encoding_df.pkl # 目标编码特征
```

> **设计哲学**：所有特征表都以 **完全相同的行顺序（index 对齐）** 存储，训练时用 `pd.concat([...], axis=1)` 横向拼接，而不是 `merge`。这样避免了 join 开销、也保证 dtype 不丢失。**这是整个代码库的性能关键**，务必理解。

> **⚠️ 本地复现偏离官方：按 store 分段生成特征**
> - **官方做法**：把全部 30490 条序列一次性 melt 成长表，生成上述 5 个**全局** pkl，峰值内存约 14GB。
> - **本地做法**：本机只有 10GB RAM，改为**一次处理一个 store**，产出 `data/processed/{store}/` 下 10 店 × 5 个 pkl；训练 / 预测脚本相应改为读取当前店的文件。
> - **等价性**：grid_part_1/2/3 和 lags_df_28 不跨店计算，数值与官方等价。mean_encoding_df 中有 7 组编码键跨店（如 `item_id`、`state_id×cat_id`），必须用"先累计 count/sum/sumsq、再回填"的两遍法才与官方等价；店内直接 transform 会算错（见 3.5 节）。
> - **额外约束**：类别列必须用全局固定类别表，index 必须多店全局唯一。
> - 具体执行规格见 `M5_复现执行手册.md` 第 3 节。

### 3.2 grid_part_2：价格特征（11 个）

```python
prices_df['price_max']  = groupby(store,item).sell_price.max()
prices_df['price_min']  = ...min()
prices_df['price_std']  = ...std()
prices_df['price_mean'] = ...mean()
prices_df['price_norm'] = sell_price / price_max          # 归一化价格
prices_df['price_nunique'] = groupby(store,item).sell_price.nunique()  # 价格变动频繁度
prices_df['item_nunique']  = groupby(store,sell_price).item_id.nunique()
# 价格动量（price momentum）
prices_df['price_momentum']   = sell_price / sell_price.shift(1)         # 周环比
prices_df['price_momentum_m'] = sell_price / groupby(store,item,month).mean()
prices_df['price_momentum_y'] = sell_price / groupby(store,item,year).mean()
```

最终 `grid_part_2` 列：`sell_price, price_max, price_min, price_std, price_mean, price_norm, price_nunique, item_nunique, price_momentum, price_momentum_m, price_momentum_y`。

**直觉**：价格弹性是零售销量的强驱动因子。`price_momentum` 捕捉"涨价/降价"的即时效应，`price_norm` 让模型感知"当前价相对历史高位"。

### 3.4 lags_df_28：滞后 + 滚动特征（模型的主力特征）

```python
SHIFT_DAY = 28   # 关键：所有 lag 至少滞后 28 天，避免数据泄漏

# (a) 固定滞后：sales_lag_28 .. sales_lag_42（15 个）
LAG_DAYS = range(28, 43)
grid_df['sales_lag_{l}'] = groupby(id).sales.shift(l)

# (b) 固定窗口滚动统计（shift 28 后再 rolling）：窗口 7/14/30/60/180
for i in [7,14,30,60,180]:
    grid_df['rolling_mean_{i}'] = groupby(id).sales.shift(28).rolling(i).mean()
    grid_df['rolling_std_{i}']  = groupby(id).sales.shift(28).rolling(i).std()

# (c) 滑动 shift 的临时滚动（供递归预测动态重算）：shift∈{1,7,14} × window∈{7,14,30,60}
for d_shift in [1,7,14]:
    for d_window in [7,14,30,60]:
        grid_df['rolling_mean_tmp_{shift}_{window}'] = groupby(id).sales.shift(d_shift).rolling(d_window).mean()
```

**为什么 SHIFT_DAY = 28**：预测目标是未来第 1~28 天。对"未来第 28 天"而言，能安全使用的最近真实观测是"今天往前 0 天"，但对"未来第 1 天"而言，最近的真实观测是"昨天"。为了**统一特征、且绝不泄漏**，训练时所有 lag 都从 28 天前起算。递归预测时再通过 `rolling_mean_tmp_*`（小 shift）动态利用刚预测出的值。

### 3.5 mean_encoding_df：目标编码（11 组 × mean/std）

```python
grid_df['sales'][grid_df['d'] > (1941-28)] = np.nan   # 遮住最后 28 天，防泄漏
icols = [
    ['state_id'], ['store_id'], ['cat_id'], ['dept_id'],
    ['state_id','cat_id'], ['state_id','dept_id'],
    ['store_id','cat_id'], ['store_id','dept_id'],
    ['item_id'], ['item_id','state_id'], ['item_id','store_id']
]
for col in icols:
    grid_df['enc_{col}_mean'] = groupby(col).sales.transform('mean')
    grid_df['enc_{col}_std']  = groupby(col).sales.transform('std')
```

**直觉**：把"某商品在某店的平均销量"这类**层级先验**注入模型，缓解冷启动、增强对小样本序列的泛化。不同模型族选取不同的编码子集（见第 4 节）。

> ⚠️ 严格的 K-fold 目标编码能进一步防泄漏，但 A1 用的是"全量分组均值 + 遮最后 28 天"的简化版。这是可复现的，也是后续可优化点。
>
> ⚠️ **本地复现偏离官方**：本地按 store 分段生成特征。上面 11 组键中，只有含 `store_id` 的 4 组在店内是完整的；其余 7 组跨店，必须用两遍法计算（先各店累计 count/sum/sumsq，合并后得到 mean/std，再回填各店），不能在店内直接 `transform`。详见本节开头的偏离说明，以及执行手册 3.3 节规则 1。

### 4.1 递归模型训练（以 1-1 recursive_store 为例）

**数据装配**（`get_data_by_store`）：

```python
def get_data_by_store(store):
    df = pd.concat([pd.read_pickle(BASE),                 # grid_part_1
                    pd.read_pickle(PRICE).iloc[:,2:],     # grid_part_2（去掉 id,d）
                    pd.read_pickle(CALENDAR).iloc[:,2:]], # grid_part_3
                    axis=1)
    df = df[df['d'] >= START_TRAIN]        # store 模型 START_TRAIN=0（用全部历史）
    df = df[df['store_id'] == store]       # 只取当前 store 的行

    df2 = pd.read_pickle(MEAN_ENC)[mean_features]     # 该族选用的编码列
    df2 = df2[df2.index.isin(df.index)]
    df3 = pd.read_pickle(LAGS).iloc[:,3:]             # 全部 lag/rolling 列
    df3 = df3[df3.index.isin(df.index)]

    df = pd.concat([df, df2], axis=1)
    df = pd.concat([df, df3], axis=1)
    features = [c for c in df if c not in remove_features]
    return df[['id','d','sales'] + features], features
```

### 4.2 非递归模型训练（以 2-1 nonrecursive_store 为例）

与递归的**关键差异**：

| 项目 | 递归 (1-x) | 非递归 (2-x) |
|------|-----------|-------------|
| seed | `42` | `1995` |
| 起始天 | `START_TRAIN=0`（store）/`700`（cat/dept） | `FIRST_DAY=710`（只用后段历史） |
| lag 特征 | 全部 lag + tmp_rolling | 只用 `sales_lag_28..42` + `rolling_mean/std_{7..180}`（**不含 tmp** ） |
| `num_leaves` | store: `2^11-1`；cat/dept: `2^8-1` | 统一 `2^8-1` |
| 验证 | 单一 `END_TRAIN-28` 窗口 | 定义多套 CV（`cv1..cv4/public/private`） |
| 模型命名 | `lgb_model_{store}[_{cat}\|_{dept}]_v1.bin` | `non_recur_model_{store}[_{cat}\|_{dept}].bin` |
| 目标 | 逐天递归预测 | 一次性预测 28 天 |

非递归模型同样固定训练 3000 轮，验证集只用于指标监控，不启用 early stopping。

### 4.3 store_cat / store_dept 的差异

- **store_cat（1-2 / 2-2）**：分组键 `store_id × cat_id`，循环 `for store in STORES: for cat in CATS:`（`CATS=['HOBBIES','HOUSEHOLD','FOODS']`）。`remove_features` 里额外去掉 `cat_id`（组内恒定）。递归版 `START_TRAIN=700`。选用的 mean encoding 列为 `enc_store_id_dept_id_*` 与 `enc_item_id_store_id_*`。

## 5. 预测与最终集成详解

对应目录：`3. code/3. predict/`

### 5.1 递归预测（1-x PREDICT）—— 核心的"逐天回填"

```python
base_test = get_base_test()   # 拼回全部 test_{store}.pkl，含 id/d/sales(未来为NaN)

for PREDICT_DAY in range(1, 29):        # 预测未来第 1..28 天
    grid_df = base_test.copy()

    # ① 用当前 base_test（含已预测的天）动态重算 tmp 滚动特征
    temp = [make_lag_roll(a) for a in ROLS_SPLIT]   # ROLS_SPLIT = shift{1,7,14}×win{7,14,30,60}
    grid_df = pd.concat([grid_df, pd.concat(temp, axis=1)], axis=1)

    # ② 对每个 store 加载模型，只预测"当天 + 该店"的行
    for store_id in STORES_IDS:
        estimator = pickle.load(open(model_dir+'lgb_model_{store}_v1.bin','rb'))
        mask = (base_test['d']==END_TRAIN+PREDICT_DAY) & (base_test['store_id']==store_id)
        base_test['sales'][mask] = estimator.predict(grid_df[mask][MODEL_FEATURES])
        # ↑ 预测值写回 base_test['sales']，供下一天的 lag/rolling 使用（递归精髓）

    # ③ 收集当天结果为 F{PREDICT_DAY}
    temp_df = base_test[base_test['d']==END_TRAIN+PREDICT_DAY][['id','sales']]
    temp_df.columns = ['id', 'F'+str(PREDICT_DAY)]
    all_preds = all_preds.merge(temp_df, on='id') if ... else temp_df
```

**递归精髓**：`make_lag_roll` 里的 `rolling_mean_tmp_*` 用的是 shift=1/7/14 的**小滞后**，在预测循环中会读到**前一天刚预测出的销量**，从而让第 t 天的特征包含第 t-1..t-14 天的信息。这正是递归比非递归"新鲜"、精度更高的原因，代价是误差会沿 28 天累积。

产物：`6. submission/before_ensemble/submission_kaggle_recursive_store.csv`（以及 `_cat` / `_dept`）。

### 5.3 最终集成（3-1 Final ensemble）

```python

sub1 = 递归_store;  sub2 = 递归_store_cat;  sub3 = 递归_store_dept

```

**为什么简单等权平均就够强**：6 份结果来自"3 粒度 × 2 模式"，彼此**误差相关性低**（不同分组、不同 lag 结构、递归 vs 直接），平均后方差显著下降。作者验证过递归准但抖、非递归稳但略偏，等权融合是稳健的折中。

> **初学者澄清 · 到底平均的是什么、最终提交什么？**
> - **只平均"预测销量"，不平均 WRMSSE。** 6 份提交各是一张"预测销量表"（30490 行 × F1..F28）；集成是对同一个格子（同商品、同一天）把 6 张表的预测值求平均：`final[id,Fk] = (sub1+...+sub6)[id,Fk] / 6`。
> - **WRMSSE 是下游的"尺子"，不是被平均的对象。** 像老师打分：先把 6 个学生的答案逐题合成一份最终答卷（逐格平均），再对这一份最终答卷**打一次分**；不是给 6 个学生各打一次分再平均分数。
> - **最终提交的就是这一份平均后的 CSV**（30490 行 × `id + F1..F28`，evaluation 段）。Kaggle 握着**未公开真值**（d_1942..d_1969 的真实销量），收到你的 CSV 后按 WRMSSE 公式与真值对比算分排名；比赛期 public 榜给暂定分，最终名次由 private 榜（即你提交的 evaluation 段）赛末公布。
> - 本轮不实现本地 WRMSSE 评分器；后续需要自评时按第 8 节边界另行建设，并以官方定义为准。

> 这里也是你后续做"对照组"最自然的切入点——可以调整**集成融合权重**（6 份提交各占多少，这是你自己方案的超参数）、加入新模型族的第 7 份结果等（见第 10 节）。注意：能调的是"融合权重"，**不是** WRMSSE 指标里的权重 `w_l`——后者由主办方固定、不可调（见 1.2 节）。

## 7. 环境兼容性改造（pandas 2.x / Python 3.10 重点）

> 官方代码写于 **2020 年（Python 3.7.6 + 旧版 pandas）**。你本地是 **Python 3.10.21 / pandas 2.3.3 / numpy 2.2.5 / lightgbm 4.7.0**。**直接跑会报错**，以下是必须处理的兼容点。

### 7.1 链式赋值失效（最高频错误）

pandas 2.x 默认开启 Copy-on-Write 语义，`df['a'][mask] = value` 这种**链式赋值不再修改原 df**（且会 `SettingWithCopyWarning`）。

官方多处这样写：
```python
grid_df['sales'][grid_df['d']>(1941-28)] = np.nan          # preprocessing
base_test[TARGET][mask] = estimator.predict(...)           # 递归预测（核心！）
sub_copy += ...                                            # 一般 OK
```
**必须改为 `.loc`：**
```python
grid_df.loc[grid_df['d'] > (1941-28), 'sales'] = np.nan
base_test.loc[mask, TARGET] = estimator.predict(grid_df.loc[mask, MODEL_FEATURES])
```
> ⚠️ 递归预测里 `base_test[TARGET][mask] = ...` 是**递归回填的命脉**，若不改，预测值写不回去，28 天全用旧特征 → 结果错误但不报错，极难排查。**务必优先修这处。**

### 7.2 `date.dt.week` 废弃

```python
grid_df['tm_w'] = grid_df['date'].dt.week        # pandas 2.x: FutureWarning/报错
# 改为：
grid_df['tm_w'] = grid_df['date'].dt.isocalendar().week.astype(np.int8)
```

### 7.3 numpy 2.x：`np.float16` 溢出与类型提升

- `reduce_mem_usage` 里对含 NaN 的 float 列强转 `float16` 仍可用，但注意 numpy 2.x 对 `float16` 的 `min/max` 比较更严格；如遇 `overflow`，把该列保留为 `float32`。
- numpy 2.x 移除了 `np.float_`、`np.int0` 等别名（官方代码未用，但第三方依赖可能用）。

### 7.4 `groupby().transform(lambda x: x.shift())` 性能

pandas 2.x 下 `transform(lambda ...)` 比旧版慢很多。`lags_df_28` 生成时若太慢，可改用向量化：
```python
# 慢（官方写法）
grid_df['sales_lag_28'] = grid_df.groupby('id')['sales'].transform(lambda x: x.shift(28))
# 快（等价，pandas 2.x 推荐）
grid_df['sales_lag_28'] = grid_df.groupby('id')['sales'].shift(28)
```
滚动同理：`groupby('id')['sales'].shift(28)` 后再 `groupby('id').rolling(...)`，或用 `transform` 但接受较慢。**功能等价即可，先保证跑通再优化。**

### 7.5 LightGBM 4.7：`verbose` / 参数名

- `lgb_params` 里的 `'verbose': -1` 在 4.x 建议改为 `'verbosity': -1`（`verbose` 仍可容忍但会警告）。
- `n_estimators` 在 `lgb.train()`（非 sklearn API）中应写作 **`num_iterations`** 或放进 params 的 `num_iterations`；官方把 `n_estimators` 放进 params 传给 `lgb.train` 在旧版能用，4.x 下 **`lgb.train` 不认 `n_estimators`**，需改：
  ```python
  lgb_params['num_iterations'] = 3000     # 替代 n_estimators
  lgb_params.pop('n_estimators', None)
  ```
- `boost_from_average=False` + tweedie 组合在 4.x 正常。

### 7.6 `pickle` 模型跨版本

官方 `5. models/` 里预训练的 `.bin` 是 **旧版 LightGBM** 存的，用 4.7 加载可能不兼容。**结论：不要指望"只预测不训练"这条路，请老老实实用第 4 节的训练脚本重新训练**（你本地无预训练模型，本就要重训）。

### 7.7 改造清单（复现前逐条 check）

- [ ] 所有 `df['col'][mask] = x` → `df.loc[mask, 'col'] = x`（尤其递归预测）
- [ ] `dt.week` → `dt.isocalendar().week`
- [ ] `n_estimators` → `num_iterations`（`lgb.train` 场景）；`verbose` → `verbosity`
- [ ] `transform(lambda x: x.shift(n))` → `groupby.shift(n)`（可选，提速）
- [ ] 每个脚本首行 `dir_` 指向本地项目根；路径变量三处统一
- [ ] `float16` 溢出列退回 `float32`
- [ ] 先跑通"预处理 + 1 个 store 的递归训练/预测"小闭环，再全量

## 8. 本地验证：WRMSSE 边界

官方 A1 代码不含 WRMSSE 计算脚本。本轮只交付预测 pipeline，**不实现本地 WRMSSE 评分器**，也不以简化公式替代官方评分。

后续如需本地评分，应留出符合时间顺序的 28 天验证窗口，并严格按竞赛 Evaluation 页面与官方 M5 定义实现全部 12 个聚合层级、RMSSE 尺度和 dollar-sales 权重。使用社区 evaluator 时也必须先核验层级、时间窗、价格连接和权重归一化口径。

> 再次区分：WRMSSE 官方指标权重由评分规则固定；递归、非递归及不同粒度预测之间的集成融合权重属于模型方案，可调整。两者不能混用。

## 9. 资源消耗与工程建议

### 9.1 资源预估（作者原始环境：2 核 CPU / 16GB RAM / Kaggle）

| 阶段 | 耗时 | 内存峰值 | 备注 |
|------|------|---------|------|
| 预处理 | 30~60 min | ~14 GB | melt 后 ~2400 万行，最吃内存 |
| 递归 store 训练（10 模型） | 每模型数十分钟~数小时 | 高 | `num_leaves=2047` 很大 |
| 递归 store_dept（70 模型） | **最久** | 中 | 模型数多 |
| 非递归（110 模型） | 中等 | 中 | `FIRST_DAY=710` 数据量小 |
| 递归预测 | 28 天 × 逐天重算 lag，较慢 | 中 | `make_lag_roll` 是瓶颈 |

**全量 220 模型在单核小内存机器上可能要跑数十小时。** 作者本人也说"每个模型约十小时"（知乎总结语，含夸张成分，实际按机器而定）。

### 9.2 加速与降内存建议

1. **先小闭环**：只跑 `store` 一族（10+10 模型）验证 pipeline 正确性，再扩到 cat/dept。
2. **`reduce_mem_usage`**：全程 float16/int8，官方已用，保留。
3. **多进程**：官方留了 `df_parallelize_run`（`multiprocessing.Pool`）但默认注释掉；你本地核多可启用加速 lag 生成。
4. **分批 gc**：官方大量 `del ... ; gc.collect()`，保留。
5. **磁盘格式边界**：Parquet / Feather 仅是通用低内存建议；本轮为兼容 A1，实际使用 `data/processed/{store}/` 下每店 5 个 pickle，不迁移现有原始 CSV 到 `data/raw/`。
6. **WSL 注意**：你在 `/mnt/e/`（Windows 盘挂载），IO 比原生 Linux 慢。若磁盘 IO 成瓶颈，可把 `data/processed/` 放到 WSL 原生盘（如 `~/`）再软链。
7. **断点续跑**：训练脚本按 store 循环，可加"已存在 .bin 则跳过"逻辑，避免中断重来。

## 10. 后续改进方向（对照实验 / 新树模型）

> 你的最终计划：在第一名基础上"多做对照组"或"把 LGBM 换成近年决策树新技术"。以下是落地建议，**均建立在第 6 节的可复现骨架之上**。

### 10.1 对照组实验设计（建议的消融矩阵）

以"6 族等权平均"的复现结果为 **Baseline**，逐一变量对照：

| 实验组 | 变量 | 目的 |
|--------|------|------|
| A. 单模式 | 只用递归 / 只用非递归 | 验证"递归+非递归融合"的增益 |
| B. 单粒度 | 只用 store / 只用 store_dept | 验证多粒度融合的增益 |
| C. 融合权重 | 改 6 份提交的加权平均（如递归 0.6 / 非递归 0.4）；指**集成权重**，非 WRMSSE 的 `w_l`（那个不可调） | 找比等权更优的融合 |
| D. zero/one 分组 | 按销量模式分组分别建模（作者探索 notebook 思路） | 验证间歇性需求专门处理是否有增益 |
| E. 目标函数 | tweedie vs poisson vs gamma vs 分类+回归两阶段 | 验证 loss 选择 |
| F. 特征 | 加/减 lag、加缺货标记、加 K-fold 目标编码 | 特征消融 |

> **关键纪律**：所有对照必须用**同一套 WRMSSE 本地验证口径**（第 8 节）和**同一随机种子**，否则结论不可信。建议每次实验记录到 `output/experiments.csv`（实验名 / 配置 / WRMSSE / 耗时）。

### 10.2 用新树模型替换 LightGBM

保持**特征工程与融合框架不变**，仅替换底层 learner，是最干净的对照：

| 候选 | 特点 | 接入方式 |
|------|------|---------|
| **XGBoost ≥2.0** | GPU 直方图、`count:poisson`/`reg:tweedie`、单调约束 | 替换 `lgb.train`，注意 DMatrix |
| **CatBoost** | 类别特征原生、Ordered TS 目标编码（防泄漏）、`Tweedie`/`Poisson` loss | 可直接吃 `cat_features`，省去部分编码 |
| **LightGBM 新特性** | `linear_tree`、DART、`feature_fraction_bynode`、GPU | 最小改动，先试 `linear_tree=True` |
| **sklearn HistGradientBoosting** | 简单基线 | 对照组用 |

**替换时的注意点：**
- Tweedie/Poisson 的**参数命名各家不同**（CatBoost 用 `loss_function='Tweedie:variance_power'`）；
- 递归预测的"回填"逻辑与 learner 无关，**替换后第 5.1 节流程不变**，只换 `estimator.predict`；
- CatBoost 的类别特征处理可能让你**删掉部分 mean encoding**，记得同步调整特征列；
- 融合层面：可以把"LGBM 6 族"与"XGB 6 族"再做一层 stacking（但注意过拟合验证集）。

### 10.3 建议的推进节奏

```
阶段 1（当前）：严格按第 6-7 节复现 A1，跑通 6 族 → submission_final.csv，本地 WRMSSE 打平基线
阶段 2：搭好 WRMSSE 评估器 + 实验记录表（第 8、10.1 节）
阶段 3：做对照组消融（10.1），确认每个组件的增益
阶段 4：引入新树模型（10.2），与 LGBM 做同口径对照 / stacking
阶段 5：把"分类 + 回归两阶段""zero/one 分组"等作者探索期想法做成新对照组
```

```
1. preprocessing/1. preprocessing.py            # 特征工程（→ 第 3 节）
2. train/1-1. recursive_store_TRAIN.py          # 递归 store
2. train/1-2. recursive_store_cat_TRAIN.py      # 递归 store×cat
2. train/1-3. recursive_store_dept_TRAIN.py     # 递归 store×dept
2. train/2-1. nonrecursive_store_TRAIN.py       # 非递归 store
2. train/2-2. nonrecursive_store_cat_TRAIN.py   # 非递归 store×cat
2. train/2-3. nonrecursive_store_dept_TRAIN.py  # 非递归 store×dept
3. predict/1-x. recursive_*_PREDICT.py          # 递归预测（逐天回填）
3. predict/2-x. nonrecursive_*_PREDICT.py       # 非递归预测
3. predict/3-1. Final ensemble.py               # 6 份等权平均
```

**核心记忆点（一页纸总结）：**

1. **特征**：grid_part_1(销量+上架过滤) / _2(价格) / _3(日历) + lags_28(滞后+滚动) + mean_encoding(目标编码)，全部 index 对齐后 `concat`。
2. **模型**：LightGBM，Tweedie(1.1) loss，lr=0.015，3000 轮。
3. **拆分**：3 粒度（store / store_cat / store_dept）× 2 模式（递归 / 非递归）= 6 族 = 220 模型。
4. **递归**：逐天预测、回填、动态重算小 shift 滚动特征；**非递归**：只用 ≥28 天 lag，一次出 28 天。
5. **融合**：6 份提交等权平均 → 最终结果。
6. **复现坑**：pandas 2.x 链式赋值（尤其递归回填 `base_test[TARGET][mask]=`）、`dt.week`、`n_estimators→num_iterations`。
